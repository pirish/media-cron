# Implementation Plan: Per-Media-Type Source & Destination Routing

**Branch**: `009-media-source-destination-routing` | **Date**: 2026-10-07 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/009-media-source-destination-routing/spec.md`

---

## Summary

The media routing subsystem introduces configurable, independent sources and destinations for each recognized media type (`music`, `audiobooks`, `books`, `movies`, `tv`), supporting multiple source types (local filesystem directories and torrent client categories/tags) and multiple destination operational types (direct structured libraries and drop/spool folders for external managers like the *arr stack). The architecture features multi-source intake aggregation, mount safety validation (preventing rogue writes to unmounted NAS drives), strict source isolation (quarantining mismatched media into review rather than polluting other libraries), and per-media transfer mode overrides, all while preserving 100% backward compatibility with global configuration fallbacks.

---

## Technical Context

**Language/Version**: Python 3.11+ (tested on Python 3.13)
**Primary Dependencies**: Python standard library (`pathlib`, `typing`, `dataclasses`, `enum`, `os`, `shutil`), PyYAML (`yaml`), `typer` for CLI ergonomics, and `pytest`/`ruff` for test verification. Zero new runtime dependencies.
**Storage**: Local filesystems, mounted network volumes (NFS/SMB), YAML configuration, and optional review quarantine staging.
**Testing**: `pytest` with mandatory Test-Driven Development (contract tests, unit tests, integration tests, end-to-end quickstart).
**Target Platform**: Linux server, container-native (Docker, Podman, Kubernetes CronJobs).
**Project Type**: Standalone Python library module and CLI media management utility.
**Performance Goals**:
- Route resolution and mount safety validation executed in <50ms.
- Multi-source directory and torrent aggregation completed without duplicate inode scans.
- Mount failure abortion in <1 second without partial file leakage.
**Constraints**:
- Strict adherence to Constitution Principle II (TDD): contract and unit tests authored and failing before domain implementation.
- Zero breaking changes for existing configurations using global `paths.source_dir` and `paths.destination_dir`.
- 100% predictive `--dry-run` simulation mode.
**Scale/Scope**: 5 core media types (`music`, `audiobooks`, `books`, `movies`, `tv`), multiple concurrent sources per media type, and structured per-media telemetry.

## Constitution Check

*GATE: Must pass before Phase 0 research. Re-check after Phase 1 design.*

- **Principle I: Library-First & CLI-Driven**: **PASS**. Domain logic isolated in `media_cron/routing/` (`resolver.py`, `engine.py`, `models.py`), fully decoupled from schedulers. Exposed via CLI entry points: `media-cron routes list`, `media-cron routes validate`, and flags on `media-cron process` with both human-readable and machine-readable JSON outputs.
- **Principle II: Test-First & Contract Verification (NON-NEGOTIABLE)**: **PASS**. Contract tests authored for `RouteResolverProtocol` and `MediaRoutingEngineProtocol`; unit and integration tests written first before domain implementation.
- **Principle III: Idempotency & Failure Resilience**: **PASS**. Non-destructive dry-run mode, atomic transfer operations, mount safety validation preventing root partition pollution on unmounted drives, and strict source isolation quarantining unexpected files into review.
- **Principle IV: Structured Observability & Diagnosability**: **PASS**. Structured telemetry per media type in `BatchSummary.routing_summary`, deterministic exit codes, and explicit diagnostic logging.
- **Principle V: Container-Native & Environment Isolation**: **PASS**. Fully configurable via YAML and `MEDIA_CRON_*` environment variables with volume mount compatibility.
